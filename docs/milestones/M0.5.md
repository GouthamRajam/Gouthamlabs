## What was built (plain English)

A written request now goes in, and comes out as a checked specification, an architecture and
RTL code that passes lint. Thirteen AI agents do the work. Real tools and fixed rules decide
whether each step passed.

| Stage | Who works | What comes out | What decides "passed" |
|---|---|---|---|
| Spec | Ivy looks up standards; Sage supplies past lessons; Iris writes the spec; Sentinel reviews it | `spec.yaml`, `spec.md` | Schema check (Appendix B.1); consistency rules (e.g. every output has a reset value); no *blocking* Sentinel finding |
| Architecture | Kepler designs; Pascal reviews size/speed/power; Sentinel reviews | `arch.yaml` | Schema check (B.2); every spec pin at the top with the right width; every requirement mapped to a module; ≥15% timing margin; no blocking finding |
| RTL | Reid hands each module to Ada (datapath), Ada-C (control) or Ada-I (interfaces); Lumen runs the checks; Watt gives power advice; Sage writes a retrospective | `rtl/*.v`, lint report | **Verilator** lint with all warnings on (0 errors, 0 warnings); **Yosys** elaboration (no latches, no loops); top-level pins match the architecture; one module per file; requirement tags in the code |

**Managers (Juno, Reid, and the directors above them):**
- give every task an assignment brief: goal, inputs, exit criteria, expected time, budget, and
  how progress is measured;
- track the 2-minute assignment rule;
- handle stalls: a task with no worker left is reassigned and resumes where it stopped;
  otherwise it is escalated one level up;
- spot-check 100% of finished work by re-hashing every output file;
- send problems a manager can't settle to the responsible human.

In Phase 0 these loops are fixed rules, not AI calls: cheap and predictable.

**Other pieces:**
- **Knowledge base:** 14 starter entries (real-world failures such as the Pentium FDIV bug,
  reset and clock-crossing pitfalls, tool tips, checklists), each with a source link, date and
  confidence. Sage adds a lesson after any failure that gets fixed.
- **Safety rails:**
  - Each agent may only read and write its own folders; the runtime refuses anything else.
  - An RTL engineer may only write the modules it was assigned.
  - The spend caps are checked before every model call.
  - Three failed attempts at the same check stop the work and call a human.

## How to run it

The API key and caps come from Settings (Live Office → Settings) or the Settings API.

## Risks and honest limits
- **Lint-clean is not correct.** Nothing in M0.5 simulates the RTL. Verilator and Yosys prove it
  is well-formed and matches the architecture's pins, not that it counts correctly. That is
  M0.6 (tests written from the spec only).
- **Open findings.** Sentinel filed 10 non-blocking findings on the final run (e.g. "the timing
  acceptance doesn't name the process corner"). Only blocking findings stop a stage, so G1
  auto-approved. They are listed for a human at G1 (`counter8_run/reports/sentinel_*.json`).
- **Pascal had no history to calibrate against.** Its size/speed estimates are first-principles
  numbers with a stated error band, not measured.
- **Results vary run to run.** Run 2 chose 2 modules, run 3 chose 3. Both passed every check.
  Cost per design will move a few cents run to run.
- **Not built yet:**
  - prompt/answer logs are kept in plain text (in the git-ignored `var/` folder), not
    encrypted as Part 7.3 asks;
  - no automatic fallback model if the model declines a request (the task fails visibly
    instead);
  - managers are rule-driven; their written daily reports come in M0.9.
- **uart is still to run.** Running it is cheap at this rate: roughly $0.5–$1, well under the $2
  cap.
