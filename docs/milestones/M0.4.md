# M0.4: Live Office web app

**Status: done.** All five Part 12.4 criteria and all three M0.4 acceptance tests (Part 13.2)
pass in real Playwright runs: a real Chromium against the real API and orchestrator, with a
real dummy run streaming over `/ws/events` (2026-10-03). `10 passed`. The backend suite is
unchanged: `175 passed, 4 skipped` (the skips are the opt-in slow OpenLane runs that CI
always runs).

## What was built (plain English)

- **The Live Office** (`web/`, Next.js + TypeScript + Tailwind). It is a web page that shows
  the AI design team as an office floor, styled after `demo/live_office.html`.
  - **Floor view.** Every division from Part 6 is a room:
    - Zone 1, Div 2 (with Zones 2A/2B/2C), Zone 3, Zone 4, Div 5, Div 6, Div 9 and Div 8;
    - Div 7, dimmed and marked Phase 2+;
    - a room of **human desks**: CEO, VP Front-End, VP Physical, VP Platform and CFO.
  - **Seats.** There are 71 in all, 66 agents and 5 humans. They are generated from
    `config/management.yaml`, so the page always seats exactly the org the orchestrator
    knows.
  - **What each seat shows:** a status ring, a "thinking" animation, the tool it is running,
    speech bubbles for what it just did, pass/fail flashes, stall and budget badges, and
    gate banners on the humans who must approve.
  - **Handoffs** fly as small packets from one seat to another.
  - **Elsewhere on the page:** a 10-stage pipeline bar, run counters, run spend, and an
    activity feed you can filter by team, agent and event type.
- **Detail panel.** Click any seat to see:
  - who it is (persona, role, mission) and its current task and progress;
  - its plan, pass/fail counts, budget used, files touched, tools used and messages;
  - its recent actions.

  In live mode it also loads `/agents/{id}` from the API.
- **Org view.** The same people as an org chart, with live status.
- **Three modes**, all feeding one event reducer so they look identical:
  - **Live** reads `/ws/events` and backfills the last 300 events. It reconnects and
    resumes where it left off.
  - **Replay** plays any stored run back at 1–50× speed, with a run picker.
  - **Demo** is a scripted run that exercises all 21 event types. It is clearly marked
    **Simulation** everywhere: a badge, a banner, a SIM tag on every feed line,
    `simulated: true` on every event, run ids `sim_run_*`, and a note on both dashboards.
    The page only goes Live when the API answers; otherwise it falls back to the labeled demo.
- **Management tab.** Backlog, running tasks, the stall list (with how long each task has
  been silent and its last evidence), assignment-SLA hit rate, and the SLAs in force.
- **Finance tab.** Spend today, total metered, budget alerts, budget vs actual per run, and
  spend broken down by source, model, agent and run. Amounts are rounded to the cent, with
  the exact value on hover.
- **Light and dark themes** follow the system setting, with a toggle to override it.
  **Phone width** stacks the rooms in one column, with the panel below.
- **Small API additions:** CORS for the web app, `GET /runs` (for the replay picker), and
  `today_usd` in the finance summary.
- **Docker Compose** now also runs `web` (the Live Office at http://localhost:3000).
- **CI** builds the web app and runs the Playwright tests.

## How to run it

```bash
docker compose up -d --build --wait     # ... api, orchestrator and web (all healthy)
open http://localhost:3000              # Live if the API answers, else the labeled demo
# or pick a mode explicitly:
#   /?mode=demo   /?mode=live   /?mode=replay&run=<run_id>&speed=10   (&theme=dark|light)

# Playwright tests: they need Postgres + Redis from compose. They start their own API +
# orchestrator on a fresh database (:8100) and their own web server (:3100), so they never
# touch the compose stack's data.
cd web && npm ci && npm run build && npx playwright test
```

## Problems hit, and what was done

- **The first fps measurement was 44.7.** A blank page in the same browser gave 60, so the
  environment was not the cause. Playwright's trace recording was. The two performance tests
  now run with tracing off (`perf.spec.ts`) and give 59.9–60.0 fps.
- **Panel latency.**
  - The first measurement, a synthetic click plus two frames, gave 107 ms.
  - Measuring properly, with the Event Timing API and real clicks, showed that the
    JavaScript takes about 1 ms. The time went on the browser re-laying out and repainting
    the whole floor.
  - Fixes: CSS containment on the rooms and panel, the floor grid on its own layer, and a
    sticky panel. The slowest click across all 71 seats is now 48–96 ms.
  - The margin to 100 ms is thin at the worst seat. That was not hidden, and the limit was
    not changed.
- **Stale visuals after a run.** These were found by looking at the screenshots:
  - a manager's STALL badge never cleared;
  - escalation toasts never went away;
  - "approved" gate banners stayed forever.

  Now a stall flag clears when that task reports progress, toasts expire after 8 s and
  decided-gate banners after 6 s. Tests assert all three.
- **The replay pipeline was wrong for partial runs.** A run stopped after Architecture
  showed all 10 stages done. Fixed: only stages actually reached are marked done. The test
  asserts exactly Spec + Arch done and nothing current.
- **Flaky local API calls** ("other side closed"). This was a keep-alive race between
  Node's fetch and uvicorn. Fixed with a longer server keep-alive and one retry in the test
  helper.
- **A Docker Hub rate limit (429)** blocked a backend image rebuild for a while. A later
  rebuild worked, and the whole compose stack (now with `web`) came up healthy.
- **Port clash.** The compose `web` uses :3000, so the tests run their own server on :3100.
  Without that, they could silently test an older container build.

## Known limits / notes for later

- **Dashboards always show current API data**, even in replay mode; there is no historical
  dashboard yet.
- **Team metrics are not computed yet.** Throughput, cycle time and first-pass yield arrive
  with the manager runtime in M0.5, and the management tab says so. Runway shows "n/a"
  until ledger data exists (M0.9).
- **All live data so far comes from the dummy agent (M0.3).** Its results are labeled
  `[dummy]` / `simulated`, and the panel and feed show those labels. Real agents come in M0.5.
- **Missing missions.** The 12 Div 6/7 teams show no mission, because the spec's tables for
  them have no Mission column.
- **Overlapping bubbles.** When several agents in one room finish within a second, their
  speech bubbles can overlap briefly (about 4.5 s). This is cosmetic.
- **Click latency on CI.** The worst-seat click latency (≤ 96 ms here) is close to the
  100 ms limit. A slower CI runner could fail it. If it does, the fix is to make the panel
  cheaper to paint, not to change the limit.
- **Desk-only humans.** Gate review, reports and project pages are not part of the Live
  Office milestone. Human desks show the gates waiting on them but cannot approve from the
  page yet; approval is `POST /gates/{id}/decision`.
