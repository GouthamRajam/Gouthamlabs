**Status: done. All four acceptance tests passed with real tool runs (2026-10-03).**
Full suite: `165 passed, 1 skipped` (including live runs of every tool and two full
OpenLane flows). The one skip is explained below.

## What was built (plain English)

Ten **adapters**, one per chip tool. Each one runs the real tool inside the `s2s-eda`
toolbox, with networking off, and returns a structured result: pass/fail, each error with
its file and line, the numbers that matter (timing slack, DRC count, LVS verdict, coverage),
the path to the raw log, the exact command, the tool's version and an environment
fingerprint.

| Adapter | Tool | What it reports |
|---|---|---|
| `verilator_lint` | Verilator `--lint-only -Wall` | warnings/errors with file:line and rule |
| `yosys_elab` | Yosys read/elaborate/check | errors, inferred latches, logic loops |
| `cocotb_sim` | cocotb on Verilator (Icarus too) | tests passed/failed, seed, line coverage |
| `sby_formal` | SymbiYosys | PASS/FAIL per property, counterexample VCD |
| `eqy` | Yosys equivalence | proven / not equivalent per partition |
| `opensta` | OpenSTA, per corner | WNS/TNS, hold slack, worst paths, violations |
| `magic_drc` | Magic, SKY130 full DRC | violation count by rule |
| `klayout_drc` | KLayout, PDK DRC deck | violation count by rule |
| `netgen_lvs` | Netgen | match/mismatch, device and net counts |
| `openlane_flow` | OpenLane 2 Classic flow | per-step status, final WNS, DRC, LVS, antenna |

**The safety net** (`backend/s2s/trust/safety_net.py`) is the single place where pass/fail
is decided. A check passes only if *all* of these hold:
1. the tool exited 0 and didn't time out,
2. the parser counted 0 errors,
3. no stage rule failed (for example: a latch, a DRC violation, an LVS mismatch, negative slack),
4. no known failure string appears anywhere in the log,
5. the tool's "I finished" marker is present.

Rule 4 is the defense against parser bugs. If the log says "Segmentation fault" or
"ERROR", the check fails even if the parser missed it and the tool exited 0. There is no
waiver or allow-list.

**Golden logs** (`backend/tests/golden/`): 25 real recorded runs (11 passing, 14
failing), at least one of each per tool. Each holds the tool's raw output, any report files,
and a `meta.json` recording exactly how it was produced. `python -m tests.capture_golden`
regenerates them, and it refuses to save a golden whose real result doesn't match its
expectation.

## Image fix (approved by you before M0.2 work continued)

While building the adapters I found the M0.1 image could not actually *run* three things,
even though M0.1's version-only self-test passed:
- Verilator simulation: no `make`, C++ compiler or `perl`.
- eqy: no `make` or `awk`.
- SymbiYosys's standard engine: no SMT solver, and the trace tool was missing a Python module.

I added `make`, `clang`, `perl`, `gawk`, `sed`, `yices` and `z3` from the same Nix package
set the OpenLane image was built with, pinned by exact store path in `eda/versions.lock`,
and fixed the trace tool. The self-test now also runs six tiny *real* jobs, so this can't
slip again:

## How to run it

```bash
docker build -t s2s-eda eda/                 # once (see M0.1)
cd backend && pip install "pytest>=8"
python -m pytest                             # unit tests + fast live runs (~1.5 min)
S2S_RUN_SLOW=1 python -m pytest              # + full OpenLane runs (~6 min total)
```

## Problems hit, and what was done

1. **Image gaps** (above). Found by actually running the tools; fixed after your approval.
2. **My first OpenLane "failing" case passed.** At a 2.5 ns clock, OpenLane's optimizer
   really met timing (+0.047 ns slack). I had assumed it would fail. I tightened the clock to
   1.0 ns, which genuinely fails. Lesson recorded in the fixture's header.
3. **My first cocotb "passing" test failed.** The real counter value at the sampling point
   is 5, not 6, because the value is read at the clock edge before that edge's update lands.
   I fixed my test's expectation. The tool was right.
4. **One safety pattern was too broad.** `not found` matched OpenSTA's harmless warnings
   about physical-only cells. Per the no-waiver rule I removed the pattern; I did not
   allow-list the warning.
5. **OpenLane reports its timing failure only on the console**, not in `flow.log` or
   `error.log`, and doesn't write `final/metrics.json` when it stops. The adapter reads the
   console log, flow.log *and* the last step's metrics, so nothing is lost.
6. **SymbiYosys writes two traces on failure.** The real counterexample is reported, and the
   induction trace is listed separately so the same assertion isn't double-counted.

## Known limits / notes for later

- The one skipped test: the "truncated log" test can't apply to OpenLane. Its success marker
  lives in `flow.log`, not the console log; the OpenLane adapter still requires it.
- `klayout_dfm` (listed in Part 7.5) is not built yet. It wasn't in the M0.2 request, and
  its checks are defined with DFM in A.15 / M0.7.
- Coverage is line coverage from Verilator only (Icarus has none). Richer coverage
  (toggle, functional) belongs to the verification milestone (M0.6).
- `opensta` runs one corner per call. Multi-corner sweeps are the caller's loop (M0.7).
- Tool runs write files into the working directory as root (Docker default). This is fine
  for Phase 0, and should be revisited when the orchestrator owns workdirs (M0.3).
- `eda/scripts/verify_gds.sh` is still the M0.7 placeholder. The DRC/LVS adapters are its
  building blocks.
