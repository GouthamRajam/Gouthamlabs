# M0.1 — EDA foundation and runner

**Status: done. All five acceptance tests passed with real tool runs (2026-10-03).**

## What was built (plain English)

- **The `s2s-eda` toolbox image** (`eda/Dockerfile`). One Docker image that has every
  open-source chip tool Phase 0 needs, plus the free SkyWater 130nm "process kit" (PDK),
  which holds the factory's rules and the library of ready-made logic cells. We don't build
  the tools ourselves. We start from the official OpenLane 2 image, locked to one exact
  build, which already holds 11 of the 12 tools as a tested set. On top of that we add two
  things: the SKY130 PDK and cocotb (the Python testbench library).
- **A version lock** (`eda/versions.lock`). The exact version of every tool and of the PDK,
  plus a security fingerprint (sha256) for every PDK file we download. If a download ever
  changes even by one byte, the build stops.
- **A self-test** (`eda/scripts/selftest.sh`). It asks each of the 12 tools for its version
  and checks it against the lock file. It also checks that the PDK is the pinned build.
  If any tool is missing, broken, or a different version, it fails.
- **Database and message queue** (`docker-compose.yml`). Postgres and Redis, each with a
  health check, ready for the platform work in M0.3.
- **CI** (`.github/workflows/ci.yml`). On every push, GitHub builds the image from scratch
  and runs the self-test.

## How to run it

```bash
# 1. Database + queue
docker compose up -d --wait        # returns when both report healthy
docker compose ps

# 2. Build the toolbox image (~8 GB; first build ~5 min)
docker build -t s2s-eda eda/
#    behind a TLS-intercepting proxy, also pass:  --secret id=proxy_ca,src=/path/to/ca.crt

# 3. Self-test
docker run --rm s2s-eda bash /opt/s2s/eda/scripts/selftest.sh

# 4. OpenLane's bundled spm example, start to GDSII, with networking OFF
mkdir -p runs && docker run --rm --network none -v "$PWD/runs:/work" s2s-eda bash -c '
  d=$(python3 -c "import openlane,os;print(os.path.dirname(openlane.__file__))")
  cp -r $d/examples/spm /work/spm && chmod -R u+w /work/spm && cd /work/spm &&
  openlane --manual-pdk --pdk-root $PDK_ROOT --pdk sky130A --scl sky130_fd_sc_hd \
           --run-tag m0.1 -j 4 config.yaml'
# results: runs/spm/runs/m0.1/  (final GDS in final/gds/spm.gds)
```

## Problems hit, and what was done

1. **The first `spm` run failed and stopped**, as it should. Its error was
   `GPIO_PADS_LEF ... sky130_fd_io.lef does not exist`. OpenLane's SKY130 setup needs the
   PDK's I/O-pad library even for designs without pads. Fix: install the same PDK library
   set OpenLane installs for itself (volare's "default" set). Standard cells are still only
   `sky130_fd_sc_hd`.
2. **The PDK downloader needs the GitHub API.** volare uses it, and it isn't reachable from
   every build machine. Fix: the Dockerfile downloads the pinned archives by direct URL and
   checks their sha256. That's more reproducible anyway (see DECISIONS.md).
3. **My first self-test PDK check looked for a marker file that this install method doesn't
   create.** It now reads the PDK's own build record (`.config/nodeinfo.json`). The check is
   just as strict; it now reads the right evidence.
4. **Docker Hub rate-limited** the first Postgres/Redis pull (HTTP 429). A retry a minute
   later worked. Nothing was changed for this.
5. Runs 1–2 in CI's history are the old placeholder workflow. They failed before any of
   this work.

## Known limits / notes for later milestones

- **No `make` in the image.** cocotb's classic Makefile flow needs it. cocotb's Python
  runner works today: an Icarus testbench ran and passed inside the image with
  `TESTS=1 PASS=1`. M0.6 (verification) must either use the Python runner or add `make`.
- **OpenLane 2.3.10 is the final OpenLane 2 release.** The project continues as LibreLane
  3.x. Upgrading is a later, deliberate decision, not a drift.
- CI warns that `actions/checkout@v4` runs on a deprecated Node 20 runtime. This is harmless
  today; bump to a newer major when convenient.
- docker-compose has only Postgres and Redis. The api, web and eda-runner services arrive
  with M0.3/M0.4.
- Phase 0 open-source sign-off means open-shuttle quality, not commercial-node quality.
